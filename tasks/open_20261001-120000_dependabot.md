# Task — Add `.github/dependabot.yml` for pip and GitHub Actions

**Repo:** philipdallen/ephapse
**Filed:** 2026-10-01T12:00:00Z by openhands `run=20261001-1200-rlm1`
**Directive:** DEC-043 (`docs/decisions/LOG.md`)
**Labels:** status:available, kind:hygiene, security

## Finding

ephapse has no `.github/dependabot.yml`, so neither its Python dependencies nor its pinned Actions are watched for advisories or updated automatically. HuB and rubato both ship a dependabot config, so this is a portfolio inconsistency as well as a supply-chain gap. ephapse pins `torch`, `transformer-lens`, and `sae-lens` exactly, which makes an advisory on any of them a silent, unprompted exposure.

## Evidence (verified against raw files)

- `ephapse/.github/dependabot.yml` does not exist.
- `HuB/.github/dependabot.yml` and `rubato/.github/dependabot.yml` exist.
- `ephapse/requirements.txt` pins `torch==2.14.0+cpu`, `transformer-lens==3.9.0`, `sae-lens==6.51.0`.
- The RLM security report recommends dependency vulnerability scanning.

## Fix

Add `.github/dependabot.yml` with two update blocks: `package-ecosystem: "pip"` at `/` and `package-ecosystem: "github-actions"` at `/`, both weekly. Copy the `labels: [dependencies]` convention rubato uses.

## Verification

`.github/dependabot.yml` exists and is valid YAML; Dependabot is enabled on the repo (Insights → Dependency graph → Dependabot).

## Out of scope / do not re-derive

Do not add secret scanning or SAST here. The auditor already scans for committed secrets and CI proves that scanner can fail; the missing piece is dependency updates only.
